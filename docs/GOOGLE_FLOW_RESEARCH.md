# Google Flow — Product and UX Research for Dramora

**Research basis:** Google's official Flow Help Centre and linked feature documentation reviewed 13 November 2026. This is product research, not a claim that Dramora should copy Google's interface, proprietary implementation, models, or branding. Flow changes frequently; verify current behavior during implementation.

## 1. Official documentation map

The [Google Flow Help Centre](https://support.google.com/flow/?hl=en) organizes help into:
- Getting started and the Flow Agent.
- Video creation and scene building/editing.
- Image creation and editing.
- Avatars.
- Custom Tools.
- Projects, assets, and collections.
- Models and supported features.
- Data/privacy management, keyboard shortcuts, project downloads, credits, and availability.
- Flow Music, with separate documentation for songs, spaces, music videos, playlists, sessions, and credits.

This research focuses on features relevant to Dramora's initial product direction. The presence of a Flow feature does not add it to Dramora's scope.

## 2. Agent behavior and sessions

Official references:
- [Use the Google Flow Agent](https://support.google.com/flow/answer/17093911)
- [Agent sessions and instructions](https://support.google.com/labs/answer/17093911?hl=en)

Documented behaviors include:
- Agent can be enabled from the prompt area in a project.
- The prompt box changes when Agent is enabled.
- Agent can be expanded into a side panel.
- Agent supports brainstorming, prompt refinement, creative suggestions, generation workflows, editing selected assets, batch generation, asset organization, and reference inputs.
- Agent conversations are automatically saved as project-specific sessions.
- Users can reopen, create, rename, and delete sessions.
- Project-level Agent instructions can guide behavior.
- Settings can control confirmation before generation and default generation preferences.
- Media generated by Agent is automatically saved to the open project.
- Deleting an Agent session clears its conversation history but does not delete generated media from project assets.
- Google's current documentation states Agent availability is web/PC only; Dramora must define its own responsive support rather than inherit that restriction.

### Dramora interpretation

- Keep the creative workspace and prompt composer as the stable primary surface.
- Provide a clear Showrunner/Agent control in the composer area.
- Expanding the Showrunner opens a side panel over or beside the workspace; it does not navigate to a separate chat page.
- The expanded panel has a clear close (X) control. Closing it returns the conversation to its compact/previous placement.
- Do not show a redundant expand toggle inside the expanded panel if the close control is the intended way back.
- Preserve workspace state, project, selected asset, composer draft, and scroll position when opening/closing the panel.
- A hamburger/menu control at the top of the panel opens project-specific sessions.
- Session history is project-scoped. Session deletion must not delete generated assets.
- Offer project-level Showrunner instructions as an advanced project setting, not a required setup step.
- Use explicit confirmation for paid image generation or destructive actions according to Dramora's own policy.

The side-panel details above include product-owner observations from hands-on Flow use; they are Dramora design requirements, not all independently stated in Google's help text.

## 3. Image generation, editing, and history

Official reference:
- [Create and edit images in Flow](https://support.google.com/flow/answer/16729550)

Documented behaviors include:
- Image creation can be requested through Agent or the standard prompt box.
- Standard image generation exposes model, aspect ratio, number of outputs, and optional ingredients/references.
- Agent can route an image request to a suitable image model based on request and inputs.
- Images can be edited with text instructions and selected reference media.
- Editing preserves the original and creates a history of previous versions and prompts.
- Earlier versions can be selected and reused as prompt references.
- Characters can be referenced by name using an @-style mention.
- Generated images and edits are saved into the project.

### Dramora interpretation

- Provide a simple prompt-first image request in Standard Mode.
- Keep advanced options secondary: aspect ratio, output count, and model/provider only when useful.
- Support selected project assets and characters as references.
- Store each output as a project asset with immutable version records.
- Preserve original images and edit prompts.
- Allow a previous version to be selected as a new reference.
- Keep image history independent from the conversation session.

## 4. Characters and voice references

Official reference:
- [Projects, assets, characters, and collections](https://support.google.com/flow/answer/16935308)
- [Create videos and add voice references](https://support.google.com/flow/answer/16353334)

Google documents reusable characters as bundles of visual and audio references. Its character workflow includes:
- Generate or upload one or more images showing the character.
- Name the character.
- Select a preset or custom voice.
- Optionally add character information.
- Reuse the character in prompts by name/mention.
- Edit character details and manage the character in the project.

Google's voice-reference documentation describes voice selection, sample preview, custom voice configuration, and use of a voice reference in supported generation modes. These capabilities depend on model, generation mode, and region; they are not universal capabilities of every model.

### Dramora interpretation

Initial character records should include:
- Name, aliases, and short identity summary.
- Detailed appearance and stable visual traits.
- Optional reference images.
- Clothing/appearance notes and continuity constraints.
- Optional descriptive voice metadata (tone, pace, accent notes) and optional user-provided reference asset.
- Prompt mention/lookup support.
- Version history and approved state.

**Scope boundary:** Dramora v1 does not create speech, clone voices, synthesize audio, or edit audio. Voice data is descriptive/reference metadata only. Do not imply that stored voice notes guarantee provider-level voice consistency.

## 5. Projects, assets, collections, and history

Official reference:
- [Manage projects, assets, and collections](https://support.google.com/flow/answer/16935308)

Documented concepts include:
- Projects as top-level creative containers.
- Project rename, download, delete, and settings.
- Asset views and filters for media types such as images, videos, characters, scenes, and uploads.
- Search and filtering.
- Collections for grouping assets, including nested collections.
- Asset deletion/trash behavior.
- Separate history/version views for edited images.
- Project and asset organization is distinct from Agent session organization.

### Dramora interpretation

- A project is the top-level user workspace.
- Conversations/sessions, assets, characters, and production records are project-scoped.
- Collections group assets without changing their ownership.
- Asset versions are separate from chat messages.
- Search/filter should work by name, type, tags, character, date, and generation status.
- Deleting a project must use clear confirmation and documented retention/deletion behavior.

## 6. Tools and reusable instructions

Official reference:
- [Create and manage Tools in Flow](https://support.google.com/flow/answer/17104535)

Flow Tools are reusable mini-apps that can be created through natural language, edited conversationally, pinned/favorited, remixed, and shared. Tool execution may consume credits; the UI warns users when a run may use credits. Custom Tool creation has plan/availability restrictions and shared tools expose their code/name/thumbnail to link recipients.

### Dramora interpretation

Do not build a public plugin marketplace or user-defined executable tools in v1. The Showrunner should have an internal, typed, allowlisted tool registry. Project-level instructions can be stored as plain text plus optional approved references. Tools must be validated, permission-checked, and auditable. Paid or consequential tool actions need clear confirmation.

## 7. Models, capability differences, and availability

Official reference:
- [Flow models and supported features](https://support.google.com/flow/answer/16352836)

Google documents that different models and subscription plans support different capabilities. Feature availability, resolution, duration, aspect ratio, references, and pricing can vary by model and region. Flow can suggest switching models when a selected model does not support a requested feature.

### Dramora interpretation

- Provider adapters must publish a capability matrix instead of assuming every model supports every feature.
- The UI should only offer controls supported by the active provider/model.
- If a capability is unsupported, explain it and offer a supported alternative rather than silently dropping user settings.
- Provider/model identifiers, settings, and capability snapshots should be recorded with generation metadata.
- Dramora must not copy Flow's model names, plans, credit system, or proprietary routing.

## 8. Data and privacy management

Official reference:
- [Manage your data in Google Flow](https://support.google.com/flow/answer/17025472)

Google documents controls for reviewing/deleting projects and outputs, deleting all project data, and managing product-improvement data settings. Its documentation warns users not to enter confidential information if they do not want it used under the applicable product-improvement settings.

### Dramora interpretation

- Publish a clear privacy/data-handling explanation before public launch.
- Provide user controls to delete conversations, assets, projects, and eventually the account.
- Explain the distinct effects of deleting a session versus deleting an asset/project.
- Avoid sending more project context to AI providers than required.
- Provider selection must include data retention, training/use, privacy terms, and regional handling in the evaluation.
- Do not imply that Dramora's data handling is identical to Google's.

## 9. Features deliberately excluded from initial Dramora scope

Flow supports video creation, video editing/scene building, avatars, voice features, custom Tools, and Flow Music. These are useful research references but do not expand Dramora's approved scope.

Initial exclusions:
- Video generation and video editing.
- Clip assembly and video rendering.
- Voice cloning, text-to-speech, and audio generation.
- Avatars and personal likeness generation.
- Music generation and music-video generation.
- User-created executable Tools or a public Tools marketplace.

## 10. UX principles extracted

1. Keep prompt interaction close to the creative workspace.
2. Do not send users to a separate chat page for Agent use.
3. Make the Agent panel expandable and dismissible.
4. Keep projects, sessions, and assets as distinct but related entities.
5. Preserve image originals and prompt/version history.
6. Make references reusable across requests.
7. Keep advanced controls secondary to the main creative task.
8. Keep internal model routing and orchestration mostly invisible.
9. Make generated media easy to find after a conversation is deleted.
10. Treat model capability differences as provider-adapter metadata, not assumptions in UI.
11. Give users understandable data deletion and privacy controls.
12. Make responsive support an independent Dramora requirement.
