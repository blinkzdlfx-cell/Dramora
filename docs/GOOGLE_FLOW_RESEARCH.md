# Google Flow — Product and UX Research for Dramora

**Research basis:** Google's official Flow Help Centre and its linked feature documentation, reviewed 13 November 2026. This is product research, not a claim that Dramora should copy Google's interface, proprietary implementation, models, or branding. Google may change feature availability and behavior; re-check official documentation during implementation.

## 1. Official documentation map

The official [Google Flow Help Centre](https://support.google.com/flow/?hl=en) groups documentation into these relevant areas:

- Get started with Flow.
- Use the Flow Agent.
- Create videos and edit videos/build scenes.
- Create and edit images.
- Create and use avatars.
- Create and manage Tools.
- Manage projects, assets, and collections.
- Models and supported features.
- Data management, keyboard shortcuts, project downloads, credits, and availability.
- Flow Music has a separate help area for songs, spaces, music videos, playlists, sessions, and music credits.

Dramora should use this map to understand the breadth of a creative workspace, while implementing only its approved initial scope.

## 2. Agent behavior

Official references:
- [Use the Google Flow Agent](https://support.google.com/flow/answer/17093911)
- [Agent sessions and instructions](https://support.google.com/labs/answer/17093911?hl=en)

Documented behaviors include:
- Agent can be enabled from the prompt area in a project.
- The prompt box changes when Agent is enabled.
- The Agent can be expanded into a side panel.
- Agent supports brainstorming, prompt refinement, creative suggestions, generation workflows, editing selected assets, batch generation, asset organization, and reference inputs.
- Agent conversations are automatically saved as project-specific sessions.
- Users can reopen, create, rename, and delete sessions.
- Project-level Agent instructions can guide behavior.
- Settings can control confirmation before generation and default generation preferences.
- Media generated by the Agent is automatically saved to the open project.
- Deleting an Agent session clears its conversation history but does not delete generated media from the project assets.

### Dramora interpretation

- Keep the creative workspace and prompt composer as the stable primary surface.
- Provide a clear Agent/Showrunner control in the composer area.
- Expanding the Showrunner opens a side panel over or beside the workspace; it does not navigate to a separate chat page.
- The expanded panel has a clear close (X) control. Closing it returns the conversation to its compact/previous position.
- Do not show a redundant expand toggle inside the expanded panel if the close control is the intended way back.
- Preserve the workspace, current project, selected asset, composer draft, and scroll position when opening/closing the panel.
- Sessions belong to projects. Session deletion must not delete generated assets.
- Offer project-level Showrunner instructions as an advanced project setting, not a required setup step.
- Use explicit confirmation for paid image generation or destructive actions according to Dramora's own policy.

The side-panel details above include product-owner observations from hands-on Flow use; they are design requirements for Dramora, not all independently stated in Google's help text.

## 3. Image generation and editing

Official reference:
- [Create and edit images in Flow](https://support.google.com/flow/answer/16729550)

Documented behaviors include:
- Image creation can be requested through Agent or the standard prompt box.
- Standard image generation exposes model, aspect ratio, number of outputs, and optional ingredients/references.
- Agent can route an image request to an appropriate model based on the request and inputs.
- Images can be edited with text instructions and selected reference media.
- Editing preserves the original and creates a history of previous versions and prompts.
- Earlier versions can be selected and reused as prompt references.
- Characters can be referenced by name using an @-style mention.
- Generated images and edits are saved into the project.

### Dramora interpretation

- Provide a simple prompt-first image request in Standard Mode.
- Keep advanced options secondary: aspect ratio, output count, model/provider only when useful.
- Support selected project assets and characters as references.
- Store each output as an asset with an immutable version record.
- Preserve original images and edit prompts.
- Allow a previous version to be selected as a new reference.
- Keep the image history independent from the conversation session.

## 4. Characters and voice references

Official reference:
- [Manage projects, assets, and collections](https://support.google.com/flow/answer/16935308)

Google describes a reusable character as a bundle of visual and audio references. Its documented character workflow includes:
- Generate or upload one or more images showing the character.
- Name the character.
- Select a preset or custom voice.
- Optionally add character information.
- Reuse the character in prompts by name/mention.
- Edit character details and manage the character in the project.

Google's voice-reference documentation describes voice selection, sample preview, custom voice configuration, and use of a voice reference in supported generation modes. These capabilities are model/mode-specific.

### Dramora interpretation

Initial release character records should include:
- Name, aliases, and short identity summary.
- Detailed appearance and stable visual traits.
- Optional reference images.
- Clothing/appearance notes and continuity constraints.
- Optional descriptive voice metadata (for example, tone, pace, accent notes) and an optional user-provided reference asset.
- Prompt mention/lookup support.
- Version history and approved state.

**Scope boundary:** Dramora's initial release does not create speech, clone voices, synthesize audio, or edit audio. Voice data is descriptive/reference metadata only. Do not imply that a stored voice description guarantees provider-level voice consistency.

## 5. Projects, assets, collections, and history

Official reference:
- [Manage projects, assets, and collections](https://support.google.com/flow/answer/16935308)

Documented concepts include:
- Projects as top-level creative containers.
- Project rename, download, delete, and settings.
- Asset views and filters for media types such as images, videos, characters, scenes, and uploads.
- Search and filtering.
- Collections for grouping assets, including nested collections.
- Asset deletion/trash behavior.
- Separate history/version views for edited images.

### Dramora interpretation

- A project is the top-level user workspace.
- Conversations/sessions, assets, characters, and production records are project-scoped.
- Collections group assets without changing their ownership.
- Asset versions are separate from chat messages.
- Search/filter should work by name, type, tags, character, date, and generation status.
- Deleting a project must use a clear confirmation and documented retention/deletion behavior.

## 6. Tools and reusable instructions

The official Flow Help Centre includes documentation for creating and managing custom Tools and adding Agent instructions.

### Dramora interpretation

Do not build a public plugin marketplace or user-defined executable tools in the initial release. The Showrunner should have an internal, typed, allowlisted tool registry. Project-level instructions can be stored as plain text plus optional approved references. Tools must be validated, permission-checked, and auditable.

## 7. Features deliberately excluded from initial Dramora scope

Flow supports video creation, video editing/scene building, avatars, voice features, and Flow Music. Their existence is useful product research but does not expand Dramora's approved scope.

Initial exclusions:
- Video generation and video editing.
- Clip assembly and video rendering.
- Voice cloning, text-to-speech, and audio generation.
- Avatars and personal likeness generation.
- Music generation and music-video generation.
- User-created executable tools/marketplace.

## 8. UX principles extracted

1. Keep the prompt interaction close to the creative workspace.
2. Avoid sending the user to a separate chat page for Agent use.
3. Make the Agent panel expandable and dismissible.
4. Keep projects, sessions, and assets as distinct but related entities.
5. Preserve image originals and prompt/version history.
6. Make references reusable across requests.
7. Keep advanced controls secondary to the main creative task.
8. Keep internal model routing and orchestration mostly invisible.
9. Make generated media easy to find even after a conversation is deleted.
10. Treat model capability differences as provider-adapter metadata, not assumptions in the UI.
